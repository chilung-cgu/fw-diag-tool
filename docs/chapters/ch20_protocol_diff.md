# Ch20 — 協定 A/B 對比分析

## 功能簡介

在韌體開發、改版驗證與硬體除錯過程中，A/B 比對（Before/After Comparison）是快速收斂問題範圍的核心手段。協定 A/B 對比分析（Protocol Diff）支援 **I2C、SPI、UART、PCIe、MCTP** 五種常見匯流排與系統協定，可直接將修改前（Baseline）與修改後（Candidate）的兩組追蹤記錄進行雙向差分比對。

系統會比對交易總數、異常消長、關鍵欄位（如晶片型號、崩潰類型、Link 頻寬、位址分佈）與呼叫棧符號，自動歸納出「新增異常」、「已解決異常」與「共同異常」，並支援匯出結構化 Markdown 對比報告。

---

## 支援協定與輸入格式

本功能提供左右雙欄獨立輸入（左欄為 Baseline，右欄為 Candidate），每一側皆可選擇**上傳檔案**或**直接貼上文字內容**。單一檔案大小上限為 20 MiB。

| 協定 | 支援格式 | 檔案副檔名 | 輸入內容範例 |
|---|---|---|---|
| **I2C / PMBus** | 解碼後 CSV、文字追蹤記錄 | `.csv`, `.txt` | Saleae 匯出 CSV（含 Time, Address, Data, Read/Write, ACK/NAK）或文字 trace |
| **SPI Flash** | 解碼後 CSV、文字追蹤記錄 | `.csv`, `.txt` | Saleae 匯出 CSV（含 Time, MOSI, MISO, CS/Enable）或文字 trace |
| **UART Crash** | 系統崩潰與轉儲日誌 | `.txt`, `.log` | Linux Kernel Panic、Oops、Call Trace 或 ARM Cortex-M HardFault 日誌 |
| **PCIe Config & AER** | 設定空間 Dump、AER 核心日誌 | `.txt`, `.hex`, `.log` | `lspci -xxxx` 輸出或包含 PCIe AER 錯誤之 dmesg 日誌 |
| **MCTP / IPMB** | 伺服器管理封包十六進位字串 | `.txt`, `.hex`, `.log` | 每行一筆完整的 MCTP/IPMB Hex 封包字串（如 `01 00 00 00...`） |

---

## 操作步驟

1. 啟動 Web 介面並由側邊欄進入 **「協定分析」** 區塊的 **「🔀 協定 A/B 對比分析」** 頁面。
2. 於頂部下拉選單 **「選擇協定」** 中選擇欲比對的協定類型（I2C、SPI、UART、PCIe 或 MCTP）。
3. 分別於 **「Baseline（基準）」** 與 **「Candidate（待測）」** 區域上傳對應檔案或貼入日誌文字。
4. 點擊 **「開始分析」** 按鈕執行雙向比對。
5. 查看頂部判定狀態、指標卡片、詳細清單，並依需求點擊 **「下載 Markdown 對比報告」**。

## 輸出結果與指標解讀

比對完成後，頁面將依協定特性呈現專屬的差異診斷摘要與 4 組 KPI 指標卡片：

### 各協定指標卡片對照

| 協定 | 指標卡片 1 | 指標卡片 2 | 指標卡片 3 | 指標卡片 4 |
|---|---|---|---|---|
| **I2C** | 新增異常數 | 已解決異常數 | 共同異常數 | 交易數變化（Delta） |
| **SPI** | 新增異常數 | 已解決異常數 | 共同異常數 | 交易數變化（Delta） |
| **UART** | 新增呼叫棧符號 | 已解決呼叫棧符號 | 共同呼叫棧符號 | 故障位址變更（相同 / 變更） |
| **PCIe** | 新增 AER 錯誤數 | 已解決 AER 錯誤數 | 共同 AER 錯誤數 | Link 降級狀態（相同 / 變更） |
| **MCTP** | 新增錯誤數 | 已解決錯誤數 | 共同錯誤數 | 訊息數變化（Delta） |

### 詳細差異清單（Expander）

下方展開式面板分類列出具體項目：

- **新增項目（New）**：僅在 Candidate 出現的異常、錯誤碼或呼叫棧符號（需優先排查是否為新版韌體引入之次生問題）。
- **已解決項目（Resolved）**：僅在 Baseline 出現、Candidate 已消除之項目（驗證 Bug 修復成果）。
- **共同項目（Common）**：兩份記錄皆存在的未解問題（仍待進一步分析之既存缺陷）。
- **位址變更（Address Changes，I2C 專屬）**：若裝置位址分佈有變動，列出新增或移除之 7-bit / 8-bit 位址。

## 典型使用場景

- **韌體升版回歸比對（Firmware Regression）**：比對修復前後的 I2C/SPI trace，確認特定 NACK 或逾時是否消除，且未衍生新異常。
- **良品與不良品對照（Golden vs Failing Board）**：將量產正常板卡與故障板卡的匯流排訊號對比，快速鎖定通信分歧點。
- **不同架構或模式切換**：比對系統在不同開機階段、電源模式或驅動設定下的 PCIe AER 錯誤與 MCTP 封包行為。

---

## 限制與注意事項

- **協定層非類比電氣**：比對基於解碼後的邏輯交易與文字日誌，無法替代示波器對電壓、雜訊、Slew Rate 或反射之類比量測。
- **交易索引對齊**：若 Candidate 存在額外的重試（Retry）或輪詢（Polling），後續交易索引可能產生整體位移，需結合時間戳與位址共同判讀。
- **日誌符號完整性**：UART 呼叫棧差異需基於相同編譯版本與 symbol 檔，避免因編譯最佳化或位址偏移造成符號誤判。
