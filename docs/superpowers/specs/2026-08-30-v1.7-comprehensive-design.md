# v1.7.0 Comprehensive Enhancement — Design Spec

> **Created via:** superpowers:brainstorming (Architectural path)
> **Date:** 2026-08-30
> **Baseline:** v1.6.0 (256b645, tag v1.6.0, 1157 tests)

## Problem Statement

After v1.6.0 added protocol statistics (SPI/UART/PCIe/MCTP), CSV export, and
unified multi-protocol reports, deep analysis reveals four systemic gaps:

1. **Statistics without visualization**: All four new statistics modules produce
   numeric data but display it only as `st.metric` cards and text tables.
   No interactive charts or trend visualizations exist, limiting actionable
   insight for engineers.

2. **Protocol maturity gap persists**: I2C has 10,512 lines across 23 modules
   with a chip database, sensor decoders, EEPROM support, MUX tracking,
   waveform diff, and timing charts. Other protocols remain significantly
   thinner:
   - SPI (2,374 lines, 9 modules): No flash chip database, no memory map
   - UART (1,499 lines, 7 modules): No symptom database, no boot classification
   - PCIe (2,241 lines, 8 modules): No topology tree, no capability decoder enrichment
   - MCTP (1,346 lines, 6 modules): No EID topology map, no message type decoder

3. **Documentation lag**: v1.6.0 added 6 major features (4 statistics modules,
   CSV export, unified report) with no MkDocs chapters. 25 GUI pages exist but
   only 23 chapters documented.

4. **Coverage gap**: The v1.6.0 coverage-boost task failed (429 rate limit).
   Branch coverage is likely still below 85% target.

## Design Goals

### G1: Interactive Statistics Charts
Add Plotly-based interactive charts to all four statistics modules, providing
visual insights that raw numbers cannot convey:
- SPI: Command frequency pie/bar chart, throughput timeline
- UART: Boot phase Gantt/waterfall chart, timestamp coverage heatmap
- PCIe: Topology sunburst, AER error category breakdown, link speed distribution
- MCTP: EID communication chord diagram / heatmap, message type distribution

### G2: SPI Flash Chip Database
Create a SPI flash chip database (mirroring I2C's chip_db.py) that identifies
flash chips by JEDEC ID, provides capacity/voltage/speed specs, and enables
GUI browsing. This is a highly practical feature for firmware engineers working
with SPI NOR/NAND flash.

### G3: UART Symptom Database & Boot Classification
Create a knowledge base of common UART boot failure patterns (kernel panic
signatures, watchdog timeouts, filesystem corruption messages, OOM kills,
driver probe failures) with severity classification and suggested actions.

### G4: PCIe Topology Tree Visualization
Parse lspci -tv output or config space data into a hierarchical tree structure,
visualize bus/device/function topology, and highlight devices with errors.

### G5: MCTP EID Topology Map
Build an endpoint discovery map from parsed MCTP packets, showing EID-to-EID
communication patterns and identifying potential routing issues.

### G6: Documentation Update
Write MkDocs chapters for all v1.6.0 and v1.7.0 features, update README with
full feature matrix.

### G7: Test Coverage Gap Closure
Close branch coverage gaps in reporting/, session/, gui/ pages, and protocol
reporters to reach 85%+ target.

## Architecture

### G1: Statistics Charts Module

Create `src/fw_diag_tool/gui/charts/` package:
- `stats_charts.py`: Protocol-agnostic Plotly chart builders
  - `pie_chart(data: dict[str, int], title: str) -> go.Figure`
  - `bar_chart(data: dict[str, int], title: str) -> go.Figure`
  - `gantt_chart(phases: dict[str, float], title: str) -> go.Figure`
  - `heatmap_chart(matrix: dict[str, dict[str, int]], title: str) -> go.Figure`
  - `sunburst_chart(hierarchy: list[dict], title: str) -> go.Figure`

Integration: Each protocol UI page calls chart builders from within its
statistics expander, rendering with `st.plotly_chart()`.

### G2: SPI Flash Chip Database

New files:
- `src/fw_diag_tool/spi/chip_db.py`: Database of common SPI NOR/NAND flash
  chips indexed by JEDEC manufacturer + device ID.
  - `SPIFlashChip` frozen dataclass: manufacturer, part_number, jedec_id,
    capacity_bytes, page_size, sector_size, voltage_range, max_freq_mhz
  - `lookup_by_jedec(mfr_id: int, dev_id: int) -> SPIFlashChip | None`
  - `lookup_by_part_number(query: str) -> list[SPIFlashChip]`
  - `list_manufacturers() -> list[str]`
  - Built-in database: ~40-50 common chips (Winbond W25Q, Macronix MX25L,
    Micron N25Q, ISSI IS25LP, GigaDevice GD25Q, etc.)

GUI: `src/fw_diag_tool/gui/pages/spi_chip_db_ui.py`
- Searchable table with manufacturer filter
- JEDEC ID lookup utility
- Auto-identification when SPI trace contains RDID (0x9F) command response

### G3: UART Symptom Database

New files:
- `src/fw_diag_tool/uart/symptom_db.py`: Pattern-based symptom classifier
  - `UARTSymptom` frozen dataclass: pattern (regex), category, severity
    (critical/warning/info), description_zh, description_en, suggested_action
  - `classify_symptoms(lines: list[str]) -> list[MatchedSymptom]`
  - Categories: kernel_panic, watchdog, oom, filesystem, driver_probe,
    hardware_error, boot_failure, security_violation
  - ~30-40 built-in patterns covering common Linux/RTOS failure modes

GUI integration: Add symptom classification panel to uart_ui.py after
timing analysis.

### G4: PCIe Topology Tree

New files:
- `src/fw_diag_tool/pcie/topology.py`:
  - `PCIeNode` dataclass: bus, device, function, vendor_id, device_id,
    class_code, link_speed, link_width, children, has_errors
  - `build_topology(configs: list[PCIeConfigSpace]) -> list[PCIeNode]`
  - `topology_to_text_tree(roots: list[PCIeNode]) -> str`
  - `topology_to_mermaid(roots: list[PCIeNode]) -> str`

GUI: Add topology tree section to pcie_ui.py using `st.graphviz_chart()`
or text-based tree rendering.

### G5: MCTP EID Topology

New files:
- `src/fw_diag_tool/mctp/topology.py`:
  - `MCTPEndpoint` frozen dataclass: eid, message_types_seen, packet_count
  - `MCTPLink` frozen dataclass: src_eid, dst_eid, message_count
  - `build_eid_topology(report: ServerMgmtReport) -> tuple[list[MCTPEndpoint], list[MCTPLink]]`
  - `topology_to_mermaid(endpoints, links) -> str`

GUI: Add EID topology section to mctp_ui.py.
