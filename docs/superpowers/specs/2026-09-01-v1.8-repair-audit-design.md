# v1.8 Repair and Regression Audit Design

> Date: 2026-09-01
> Status: Approved by user direction to continue with a repair-only v1.8 audit.
> Baseline: local `main` at `417d909`, with v1.7.0 tag preserved at `9bbc2c4`.

## Problem

The Dashboard quick-launch labels render, but navigation is not usable after the release-notes work. `_render_quick_link()` passes URL slugs to `st.page_link()`. Streamlit 1.62 treats a string as a Python page source path, raises `StreamlitPageNotFoundError` for values such as `i2c-diagnosis`, and the broad fallback converts the failure into non-clickable caption text. Existing bare-mode tests do not create a navigation context, so they remain falsely green.

## Goal

Repair existing navigation and detect regressions across the project without adding product capabilities or changing the package version. The repaired branch must prove that Dashboard quick actions, release-note CTAs, and quick-import navigation resolve to registered pages in a real Streamlit navigation context.

## Non-goals

- No new protocol analyzers, UI panels, data formats, or user-facing capabilities.
- No `pyproject.toml` version bump, tag rewrite, push, or merge to `main`.
- No replacement of safe internal navigation with arbitrary HTML or external URLs.

## Design

Use one route registry as the source for `app.py` page registration and Dashboard links. A route entry carries the URL slug, callable page, title, and icon. The Dashboard resolves a slug to the registered `st.Page` object before calling `st.page_link()`. Unknown routes fail explicitly in tests and produce a localized warning at the UI boundary rather than silently becoming text.

The registry remains compatible with the existing `PAGE_INDEX` search metadata. Existing pages and callbacks are reused; no new page is introduced. Release-note `page` fields continue to be filtered through registered routes.

## Evidence boundaries

- Streamlit `AppTest` with the real app entrypoint or an equivalent `st.navigation` harness is runtime evidence for page registration and link target metadata.
- Direct helper calls without a ScriptRunContext are only unit evidence and cannot prove navigation.
- Full pytest, ruff, mypy, MkDocs, and lock checks are local evidence only; remote CI and release publication remain separate.

## Acceptance criteria

1. Every Dashboard quick action emits a registered internal page link with a non-empty page script hash.
2. Release-note page CTAs and quick-import links use the same registry and remain clickable.
3. Unknown slugs are surfaced deterministically and cannot produce unsafe external navigation.
4. Existing project tests remain green, including package/resource and documentation contracts.
5. No new feature behavior or version metadata is introduced.
