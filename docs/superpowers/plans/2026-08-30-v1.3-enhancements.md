# fw-diag-tool v1.3.0 Enhancement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix critical batch.py bug, surface 3 existing diff engines and session comparator as GUI pages, integrate toast notifications across analysis pages, and enhance HTML report with print/TOC/collapsible features.

**Architecture:** Each task is an independent vertical slice (new page, bug fix, or cross-cutting enhancement) that can be implemented and tested in isolation. New GUI pages follow the established pattern in `gui/pages/` with a single `render()` entry point registered in `app.py`.

**Tech Stack:** Python 3.10+, Streamlit 1.62.0, Plotly, Pydantic V2, pytest, ruff, mypy

**Spec:** `docs/superpowers/specs/2026-08-30-v1.3-enhancements-design.md`

## Global Constraints

- Python >= 3.10 (no `tomllib`, no 3.11+ features)
- `uv run` for all project commands
- All existing 891 tests must keep passing after every task
- `uv run ruff check src/ tests/` must stay clean (known batch.py issue is Task 1)
- `uv run mypy src/fw_diag_tool/` must stay clean
- zh-TW localization for all user-facing strings
- Zero-LaTeX policy: no `$...$` or LaTeX macros in any string
- Git identity from existing `~/.gitconfig` — never override
- New GUI pages must follow existing pattern: single `render()` function, registered in `app.py`
- All new `render()` functions must call `render_page_footer()` from `gui/shared.py`
- Import `from fw_diag_tool.i18n import t` for translation; register keys in `i18n/domains/gui.py`

**Interfaces:**

- [ ] **Step 1: Read the buggy code**

Read `src/fw_diag_tool/reporting/batch.py` lines 160-195 to understand the context. The bug is:
- Line 169: `i2c_report = engine.analyze_csv_file(...)`
- Line 171: `i2c_report = engine.analyze_text(...)`
- Line 174-175: `I2CReporter.generate_markdown(report, ...)` — `report` is undefined
- Line 188: `report.issues` — `report` is undefined

- [ ] **Step 2: Write the failing test**

Create `tests/test_batch_bug_fix.py`:
```python
"""Test that batch_analyze_directory handles I2C files without NameError."""
from pathlib import Path
from fw_diag_tool.reporting.batch import batch_analyze_directory

def test_batch_i2c_no_name_error(tmp_path: Path) -> None:
    """batch_analyze_directory must not raise NameError for I2C CSV files."""
    csv_file = tmp_path / "test.csv"
    csv_file.write_text(
        "Time,Packet ID,Address,Read/Write,Data,ACK/NACK\n"
        "0.001,0,0x50,Write,0x00,ACK\n"
    )
    results = batch_analyze_directory(str(tmp_path))
    assert isinstance(results, list)
    assert len(results) >= 1
```

- [ ] **Step 3: Run test to verify it fails**

Run: `uv run python -m pytest tests/test_batch_bug_fix.py -v`
Expected: FAIL with NameError on `report`

- [ ] **Step 4: Fix the bug**

In `src/fw_diag_tool/reporting/batch.py`, change lines 169-171 from:
```python
i2c_report = engine.analyze_csv_file(str(file_path))
# ...
i2c_report = engine.analyze_text(...)
```
to:
```python
report = engine.analyze_csv_file(str(file_path))
# ...
report = engine.analyze_text(...)
```

This makes the downstream `report` references on lines 174-175 and 188 valid.

- [ ] **Step 5: Run test to verify it passes**

Run: `uv run python -m pytest tests/test_batch_bug_fix.py -v`
Expected: PASS

- [ ] **Step 6: Run ruff to verify clean**
